# 用 prompt 請 AI 做這款遊戲

這份文件記錄：如果要從零請 AI 做出「芒果園保衛戰」，prompt 應該怎麼寫。

重點不是寫「做一個像 XX 的遊戲」，而是把開發過程中踩過的坑先寫死：核心循環、目標進程、手感數字、UI 規格、驗收方式。
AI 最常做錯的就是「只換殼、沒手感、目標不清楚」。

## Prompt

````markdown
# 任務：做一款網頁遊戲「芒果園保衛戰」

## 一句話
俯視角、手機直式優先的放置採集遊戲：農夫在果園採芒果、趕偷水果的台灣獼猴，
回路邊水果攤賣給排隊客人，買升級和請工人，最後打倒深山裡的猴王。通關時間就是分數。

## 核心循環（每個動作都要一看就懂）
1. 走近果樹或猴子會自動揮竹竿攻擊（不用按鍵），芒果／搶回的香蕉自動進背包
2. 背包滿了，東西掉在地上成一堆，之後再撿
3. 站上水果攤前的圓圈，排隊客人一次買一個（香蕉先賣），每人買 3 個換下一位
4. 站上其他建築的圓圈打開升級選單：農會（請工人）、農具行（工具/範圍/雨鞋/護具）、柑仔店（背包/收購價/販賣速度/宅配）
5. 裝備夠了去地圖西南角打猴王，打倒就結算

## 世界
- 地圖 4800×3200，四區：淺山果園（北，★★）、深山猴區（西南，★★★，猴王）、果園村（中南，★，基地）、市郊（東南，★☆）
- 危險度同時乘上「受到傷害」和「掉落量」，危險＝報酬
- 建築周圍是安全區；果樹樹幹、建築主體是實體，採收後的樹可穿過
- 地圖外圍鋪山林地面，鏡頭永遠不能露出背景色

## 數值（照抄，不要自己發明）
見附件 docs/reverse-engineering.md：難度、12 種升級價格、工具傷害/間隔、
猴子血量/速度/視野/放棄追擊距離、據點、猴王、里程碑、陷阱。

## 目標進程（最重要，決定好不好玩）
- 每場開始：「通關目標」卡 → 3-2-1-出發！倒數 → 計時
- 第一次玩有 6 步任務欄，左上角顯示，金色箭頭繞著主角指方向：
  1 裝滿背包 → 2 回攤賣掉 → 3 請一個採果工 → 4 升級採果工具 → 5 加大背包 → 6 打倒猴王
- 箭頭只在「買得起」時才指向建築，否則顯示「先存到 $X（目前 $Y）」
- 背包 ≥85% 時任務欄變紅色提醒，箭頭改指水果攤
- 最後一步提示「現在買得起的下一個升級」，打開該建築選單時高亮那一列
- 里程碑：趕走 60 隻猴子 → 全部升級 8 折；採收 100 棵樹 → 工人過勞（速度減半、宅配變慢）。兩者合起來把玩家從安全區推向危險區
- 成就卡（17 個，銅/銀/金）跳出時遊戲和計時暫停；建築選單、倒下畫面不暫停

## 手感（逐條實作，這些就是「流暢」的來源）
- 模擬以秒計，每幀 dt 上限 0.1 秒；移動即走即停，無加速度
- 鏡頭硬鎖主角（不要平滑跟隨），並依 HUD 和選單高度位移，讓主角在可見區域中央
- 主角四方向各 4 格走路動畫 8fps；攻擊動畫 4 格，播放時間剛好等於攻擊間隔
- 傷害在揮到一半才結算，揮擊時面向目標，可以邊走邊揮
- 打擊回饋：被打的東西白閃 60ms、樹左右抖兩下、猴子 200ms 淡出、據點被壓扁
- 只有主角受傷時鏡頭震動（80ms）；不要加 hit-stop、擊退、粒子
- 飄字 15px 往上 26px、800ms 淡出；賣東西的「+$」每 0.3 秒合併一次
- 程式產生的 8-bit 音效：揮擊、擊殺、受傷、任務完成、成就，加循環背景音樂

## 狀態效果（用生活化的原因，不要「中毒」「著火」）
被大公猴抓傷流血（持續扣血）、被猴王撞倒扭到腳（變慢）、
剉冰店吃太多冰肚子痛（變快但扣血）、朝天椒田辣椒手（打到的猴子持續扣血）、
拆猴群據點後手腳俐落（攻速 ×2）、廟口涼亭要投香油錢（猴子不靠近、快速回血）

## UI 規格
- 字型 Cubic 11（俐方體11號，OFL 授權，附授權檔）
- NES 調色盤：夜藍 #01215b、金 #f8b800、海軍藍 #24188c、白 #fcfcfc、紅 #d82800
- 零圓角、3–4px 黑框、硬陰影；按鈕按下位移 2px；出現的元件都用同一個彈出動畫（0.6→1.15→1，350ms）
- HUD：計時、聲音/暫停、狀態徽章、錢/芒果/香蕉、背包條、危險度＋猴王血條；下方左任務欄、右小地圖
- 建築選單是 440px 底部抽屜，每列：圖示、名稱 Lv、說明、價格按鈕（買不起變灰、按了會抖）
- 手機直式；電腦全螢幕，鏡頭依視窗高度縮放（約看到 600px 高的世界）

## 美術
- 16-bit 像素風、俯視 3/4 角、暖色、1px 深色外框，以 2 倍解析度繪製、顯示時縮半
- 角色用 sprite sheet（固定格線、同一基準線、整張共用一個裁切框），逐格切出
- 素材清單見 docs/assets.md

## 技術
- Vite + React（選單/HUD）+ Phaser（世界）+ TypeScript
- 所有規則放在不依賴 Phaser 的 headless `Game` 類別：`step(dt, input)` + 查詢，Phaser 只負責畫
- Vitest 測 `Game` 的公開介面；Playwright 跑一條完整流程（標題→採收→賣出→打倒猴王）

## 驗收
- 每個機制有單元測試；e2e 連跑多次都要通過
- 手機 412×860 和電腦 1440×900 都截圖檢查：不能有色塊、背景色外露、元件被遮
````

## 使用建議

1. **不要一次丟全部。** 照這個專案的順序分階段做：
   - 先做 headless 規則和測試
   - 再接畫面和手感
   - 再做目標進程
   - 最後打磨 UI

   每階段截圖確認後再往下。
2. **數值和參考文件直接附上，不要讓 AI 自己猜。** 這三份文件可以直接當附件：
   - [`reverse-engineering.md`](reverse-engineering.md)：玩法數值
   - [`feel-reference.md`](feel-reference.md)：手感與目標進程
   - [`ui-reference.md`](ui-reference.md)：視覺與版面
3. **美術另外開一條線處理。** 要求用 sprite sheet、固定格線、共用裁切框，不然動畫會抖。清單與後製規則見 [`assets.md`](assets.md)。
4. **「手感」那段最不能省。** 少了它，AI 做出來的通常就是會動但很鈍的空殼。這個專案第一版就是這樣，試玩時被指出「主題很怪、沒有揮擊動畫、版面粗糙」。

## 這個專案實際踩過的坑

| 問題 | 原因 | 寫進 prompt 的對策 |
|---|---|---|
| 主題換了但動作不合理（拿球拍砍樹） | 只把名詞替換，沒檢查「動作 → 目標」是否直覺 | 「每個動作都要一看就懂」＋明確的對應 |
| 沒有揮擊動畫、手感鈍 | 只生單張圖，用縮放假裝動畫 | sprite sheet 規格＋動畫時間綁定攻擊間隔 |
| 不知道下一步要做什麼 | 任務提示只是一行文字 | 6 步任務、箭頭只在買得起時出現、紅色提醒 |
| 狀態效果出戲（中毒、著火） | 沿用原作術語 | 「用生活化的原因」並列出每個狀態 |
| 畫面小又糊 | 照抄手機版縮放 0.7，2x 素材被縮小 | 依視窗縮放，2x 素材在 Retina 上 1:1 |
| 走到邊緣或開選單露出藍底 | 鏡頭範圍超出地圖 | 地圖外圍鋪地面、鏡頭不能露出背景色 |
| 主角被樹或建築蓋住 | 沒有碰撞 | 樹幹、建築主體是實體 |
